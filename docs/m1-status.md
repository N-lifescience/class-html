# M1 구현·검증 현황

2026-10-03에 Task 9 리뷰를 마무리하고 Task 10~13을 구현했습니다. 학교 전자칠판에서의 실기 확인은 남아 있습니다.

## 구현

- Task 9: 툴바·색/반 메뉴의 Enter·Space 입력을 장 넘기기와 분리하고, Esc로 팝오버를 닫습니다. 좌우 툴바 버튼의 최소 크기는 52px입니다.
- Task 10: 같은 버튼에서 칠판/슬라이드를 전환합니다. 반별 칠판 추가·삭제·번호·판서, 5종 바탕, 초록 바탕의 흰 펜, 원래 슬라이드와 단계 복귀를 지원합니다.
- Task 11: 움직임 끄기·인쇄 판서 포함·손바닥 지우기 설정을 저장합니다. 어절 줄바꿈은 원래 요소와 이벤트를 보존하며, 다시 적용해도 중첩하지 않습니다.
- Task 12: 한 장에 한 쪽으로 단계가 펼쳐진 인쇄를 지원합니다. 형광펜과 펜을 분리 합성하고 판서가 있는 칠판을 포함할 수 있습니다. `D`, `?audit`, `ClassHTML.audit()`로 자동 점검합니다.
- Task 13: `examples/m1-demo.html`에 판서·단계·조판·칠판·버튼·슬라이더·저장 확인용 시험 덱을 마련했습니다.

판서 중 장이나 반을 바꾸면 미완성 입력을 취소합니다. 진행 중인 지우개가 제거한 획은 복구하고 다시 저장합니다. 자동 점검은 장·단계·칠판·판서 입력을 보존하고 수업의 show/hide 훅을 호출하지 않습니다.

## 재현 명령

Node.js 22 이상과 Chrome 또는 Edge가 필요하며 npm 설치는 필요하지 않습니다. 다음 명령은 저장소 루트에서 PowerShell로 실행합니다.

```powershell
node tools/build.mjs
node --test "tests/unit/*.test.mjs"
$testPages = Get-ChildItem tests/browser/*.test.html | ForEach-Object { $_.FullName }
node tests/run-browser.mjs @testPages
node tests/run-demo.mjs
```

소스를 바꾸면 브라우저 테스트 전에 반드시 빌드합니다. `run-demo.mjs`의 화면 캡처·백업·JSON 보고서는 실행 결과에 표시된 임시 폴더에 남습니다. 실제 브라우저 입력과 새로고침으로 저장·백업을 검증하며 사용자 브라우저 프로필을 사용하지 않습니다.

## 검증 결과

- 단위 테스트 29개, 브라우저 페이지 테스트 134개 통과.
- 시험 덱 1280×720·1920×1080·3840×2160에서 자동 점검 오류 0건.
- 세 해상도에서 실제 입력·반 전환·새로고침·백업 파일 왕복 33항목 통과. 자동 점검 경고도 0건이며 표지와 초록 칠판 화면을 확인했습니다.
- 실제 PDF: 시험 덱 7장 → 7쪽. 별도 시험에서 슬라이드 4장 + 판서 칠판 1장 → 5쪽, 판서 제외 → 4쪽. 페이지는 16:9입니다.
- 엔진의 금지 API·ES 모듈·운영체제 움직임 설정 사용 여부를 규칙 테스트로 검사합니다.

## 전자칠판 실기 확인

학교 교사 PC에서 `examples/m1-demo.html`을 Chrome·Edge·웨일로 열어 아래 사항을 확인하면 M2에 반영할 수 있습니다.

1. 실제 전자펜의 획 끊김·입력 지연과 슬라이더 조작. 브라우저 자동화의 전자펜 입력은 엔진 없는 기본 슬라이더도 움직이지 않아 이 항목은 마우스·터치로 검증했습니다.
2. 두 번째 손가락·손바닥 입력, 손바닥 지우기 설정의 효과.
3. 아래·왼쪽·오른쪽 툴바의 조작 편의.
4. 학교 PC 재부팅 후 판서 유지 여부와 백업 복구.

M2의 테마·공통 부품·PPT 그림 채우기·오프라인 저장은 아직 구현하지 않았습니다. GitHub 원격 저장소나 공개 배포는 만들지 않았습니다.
